## 逐项处理

| 问题 | 修复 | 证据 |

| F4 输入焦点丢失 | 字段 change 使用不重绘提交；完成时不替换 DATA、不重建编辑器，不再整页 inert；保存串行排队 | browser：延迟保存时点击新属性输入并键入，内容/焦点保留；连续修改两个字段都保存 |
| F5 超时与不确定提交 | 每请求 8 秒超时，网络异常仅重试一次且同 body/requestId；请求 ID 与 digest 在 SQLite 原子记录；明确 HTTP 错误不重试 | browser：提交后丢响应仅增加一个版本；持续挂起最终失败但输入可用且草稿保留；API：同 ID 重放与不同内容冲突 |

| F7 升格提示提前 | 提示标为当前编辑中的升格、等待保存；失败明确说明尚未生效 | browser：冲突导致升格保存失败，等待与失败提示出现，库中原对象仍为属性 |

| F9 无限历史与全量轮询 | 默认仅保留最近 200 版本；事务清理对应快照/请求，限制可配置；新增只回版本和时间的 revision 接口 | API：revision 内容正确；临时库配置保留 3 份，多次写后计数为 3 |
| F10 hash 不导航 | 管理台重读 hash 参数；有草稿时提示先处理；星图 hashchange 重载并按新参数恢复 | browser：管理台名称切换到 C#，星图 hudName 精确切换到 C# |

## 版本与恢复

本次修复版本 0.1.1，摘要见 [CODE_BASELINE_0.1.1](CODE_BASELINE_0.1.1.json)。旧版摘要见 [CODE_BASELINE_0.1.0](CODE_BASELINE_0.1.0.json)。原独立审核中的摘要和结论针对旧版，不能与后续集成候选摘要逐项相等比较。

旧 schema 升级为 1 会增加 requests 表；旧 snapshots 内容继续使用。若需回退应用，应先停止服务、保留当前库与草稿，使用 `.before-v1-*` 升级前备份恢复到另一个文件再启动旧版，不直接删除个人工作目录。恢复 JSON 会生成新快照并触发保留策略，旧版本不是永久可取。

本地服务更新后，已有浏览器页面应刷新再编辑；版本过旧页面保存可能被拒绝，先导出其编辑。修复没有改变初始数据或云端配置。原审核的主站接入条件仍有效：鉴权、D1、多端访问、迁移与发布流程需要另行实现和审核。
