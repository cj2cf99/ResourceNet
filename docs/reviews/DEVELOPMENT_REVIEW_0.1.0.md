## 需要优先检查的问题

以下是代码核对发现的风险与验证缺口，不表示已修复，也不冒充第三方审核结论。

| 编号 | 重点 | 影响与建议 |
| --- | --- | --- |
| R01 | 模板元数据未统一 HTML 转义 | API 可保存模板字段，部分直接进入 innerHTML；应统一转义并增加恶意文本回归 |
| R02 | 保存无超时、无幂等请求标识 | 页面可能持续 inert；提交成功但响应丢失时误报失败；应设计超时、结果核对及编辑保留 |
| R03 | 保存失败回退旧缓存 | 冲突或断线的本次编辑会丢失；至少保留可导出的失败草稿，避免刷新前失去内容 |
| R04 | API 只校验最终结构 | 直接 API 可执行界面未开放的降格、整树删除、模板更改；需确认受信本地快照接口边界，或增加操作约束 |
| R05 | 输入模式与错误分类不完整 | 空字符串 parent、未知字段、畸形模板对象及 null 请求体等需补测试与规范化；部分异常返回 500 |
| R06 | 全量快照与无限历史 | 每次保存、轮询成本与数据总量相关；无压测与保留策略，不可把数量上限当作已验证容量 |
| R07 | 导入提示反复出现 | 旧键保留且无迁移标识，刷新后仍可能再次导入旧版覆盖新编辑；需增加导入记录或更明确提示 |
| R08 | 用例覆盖未达完整验收 | 三个自动化测试不是 AC01—AC18 全覆盖；浏览器验收脚本未入库，恢复 CLI 尚无自动化集成测试 |
| R09 | 空库竞争及损坏数据处理 | 多实例空库初始化、数据库 schema 升级、损坏恢复与磁盘故障未覆盖 |
| R10 | 本地访问边界 | 无用户鉴权和 TLS；无 Origin 的本地客户端可写；不能直接公开监听或发布 |

另需确认原型的无焦点总览是否符合最终产品预期，以及 fn 创建时可空是否接受。页面依赖 Google Fonts 的外部请求，性能历史数字来自原型测量，本轮没有重新进行性能基准。

## 审核者可执行步骤

1. 复算 CODE_BASELINE 中每个文件的 SHA-256，检查与本地一致。
2. 使用 Node 24+ 执行 `npm test` 和 `npm run check:data`，确认测试不指向默认个人数据库。
3. 另设 `MYNET_DB` 为临时审核数据库、`PORT` 为未占用端口后启动 `node server.mjs`。不要用个人工作数据库试验异常输入。
4. 在管理台新建根、添加属性、由属性发起关系、将另一属性选作关系目标；核对起点不升格、目标升格、身份与父级保留。
5. 检查隶属自环与后代移动阻止、不同类型关系共存、关联回祖先允许、重复关系阻止。
6. 按 REQUIREMENTS 的 Cloudflare—Worker—GitHub 样例验证距离 1/2、属性零距离与升格后一跳。
7. 打开两个管理台页面，先在 A 保存，再在旧 B 保存，核对 B 被拒绝且 A 内容未被覆盖；同时确认 B 的失败编辑是否能够满足预期恢复体验。
8. 导出临时数据，另做修改，再执行 restore-data 命令核对恢复；停止并重启服务，检查数据不丢失。
9. 在临时环境验证 R01—R10，尤其检查 API 直接写模板字段、异常 JSON、断线和空星域，记录真实结果。

## 数据、配置和恢复影响

应用首次运行会创建 `.local` 与快照表；没有复制或修改任何已有云端库，也无数据回填或 Cloudflare 配置影响。历史浏览器数据不自动搬迁；数据库种子升级不自动合并到已保存数据库。

默认 `.local/` 已被 .gitignore 排除，备份中可能含个人输入，不应提交。代码回退不自动回退数据；若代码模型发生变化，应先做备份并验证旧代码是否仍能读取当前快照。当前没有 schema 升级，尚未发生跨 schema 回退。

恢复方案以当前快照 JSON 导出和停止服务后的数据库目录备份为主，操作见 README。历史快照不是异地备份，删除数据库目录会同时丢失其中所有版本。
